# @epinoic/specialist-routing

> **Status: synthetic catalogue, no live inference, not calibrated, nothing enabled.**
> The knowledge-base packages could not be read, so the catalogue is built from a
> hand-written overlay and the roster (`synthetic: true`). No model, adapter or
> provider was called. The only policy that can run is a `fixture-only` policy with
> arbitrary thresholds inside an explicit offline harness. `PRODUCTION_POLICY` is
> unapproved and returns `unavailable/calibration_missing`. This package enables no
> specialist; availability comes only from the runtime's capabilities object.

Contract: [`docs/handoff/specialist-routing.md`](../docs/handoff/specialist-routing.md)
(`epinoic.specialist-routing.v0.1.0`). Capabilities shape: section 9 of
[`docs/handoff/website-specialist-integration.md`](../docs/handoff/website-specialist-integration.md).
Roster: [`agents/agents.json`](../agents/agents.json).

## Purpose

A portable selection layer for the 16 IB specialists. Given provider-neutral
classification evidence, it selects at most one canonical specialist slug, asks for
clarification, or reports unavailability. It never answers, invokes an agent, calls
a model or the Fastino adapter, parses HTTP, fans out, retries, falls back, mutates a
conversation, reads browser route IDs or prompt text, stores provider/model choices
or keys, or decides enablement. Website 01 keeps ownership of `src/router/`, the
Fastino GLiNER adapter and PR19's English/History calibration.

`selectSpecialist` and `selectSticky` always resolve to a deep-frozen RoutingResult
and never mutate inputs. They throw `TypeError` only for programming errors in
`options` (not an object, unknown key, non-boolean `offlineFixtureHarness`).

## Result codes

```js
RoutingResult = {
  schema: "epinoic.routing-result.v1",
  outcome: "route" | "clarify" | "unavailable",
  slug,            // only for route; always a catalogue slug that capabilities mark available
  reason,          // closed code below
  candidates,      // [{ slug, available }] in catalogue order: clarify options, or the recognised slug for specialist_unavailable
  path,            // "classification" | "sticky"
  identity: { catalogueSha256, labelSetSha256, policyVersion, calibrationFingerprint },  // null where not verified
  inferencePerformed: false
}
```

| Outcome | Reasons |
| --- | --- |
| `route` | `single_subject`, `trusted_course_metadata`, `sticky_subject` |
| `clarify` | `generic_family`, `competing_subjects`, `overlap_policy`, `mixed_request`, `needs_task_context`, `low_confidence` |
| `unavailable` | `specialist_unavailable`, `out_of_scope`, `unsupported_language`, `calibration_missing`, `calibration_mismatch`, `identity_mismatch`, `evidence_invalid`, `capabilities_invalid`, `fixture_policy_rejected`, `sticky_invalid` |

Input problems map onto the closed enum (the contract has no separate code):

| Problem | Reason |
| --- | --- |
| Invalid catalogue, or a label set that is not `buildLabelSet(catalogue)` | `identity_mismatch` |
| Evidence `catalogueSha256` / `labelSetSha256` / `labelSetVersion` mismatch | `identity_mismatch` |
| Invalid capabilities; `offline-test` capabilities without `options.offlineFixtureHarness` | `capabilities_invalid` |
| Structurally invalid policy; unapproved policy; no thresholds or calibration | `calibration_missing` |
| `fixture-only` policy without the harness flag | `fixture_policy_rejected` |
| Invalid evidence; invalid `trusted`; missing or invalid `options.limits` | `evidence_invalid` |
| Missing or malformed `options.calibrationContext`; any fingerprint difference | `calibration_mismatch` |

## Policy order

Implemented in `src/select.js` and tested step by step (`test/select.test.js`,
"policy order"). Thresholds come from the policy; `>=` throughout.

1. Validate catalogue (and that the label set is the one derived from it), then
   capabilities, then policy (`fixture_policy_rejected`, `calibration_missing`), then
   evidence and `trusted` (`evidence_invalid`), then identity hashes
   (`identity_mismatch`), then the calibration fingerprint (`calibration_mismatch`).
2. `non_english_input >= nonEnglishMin` -> `unavailable/unsupported_language`. Only the
   flag decides; a Spanish B course score never counts as input language. No script
   detection is done or claimed.
3. Mixed -> `clarify/mixed_request` when any of: `mixed_request >= mixedMin`; two
   **unrelated** topics, where topics are subjects `>= routeMin` and family signals
   `>= familyMin`, and two topics are related only if they share a family or an
   overlap group; `out_of_scope >= outOfScopeMin` together with any topic (a
   supported half plus an unsupported or out-of-scope half). Candidates are the
   topic subjects plus the members of strong families. Never reduced to one half,
   never fanned out.
4. `out_of_scope >= outOfScopeMin` and no subject `>= routeMin` -> `unavailable/out_of_scope`.
5. A family signal `>= familyMin` whose top member is not **separated** (top member
   `>= routeMin` and more than `marginMin` above the next member) ->
   `clarify/generic_family` with all members. Exception: trusted `courseSlugs` contain
   exactly one member -> route `trusted_course_metadata` (subject to step 9).
6. `needs_task_context >= taskContextMin` and no subject `>= routeMin` ->
   `clarify/needs_task_context`, candidates at `clarifyFloor`.
7. Top subject `< routeMin` -> `clarify/low_confidence` with candidates `>= clarifyFloor`,
   or `unavailable/out_of_scope` when there are none.
8. Top two within `marginMin` (a gap within `MARGIN_EPSILON = 1e-9` of the margin counts
   as within, so float noise cannot decide a route): if every near-top subject is in
   one overlap group -> `clarify/overlap_policy`, resolved only when exactly one
   member of that group is a trusted course **and** it is a near-top candidate;
   otherwise `clarify/competing_subjects` (no trusted resolution, no tie-break).
9. The chosen subject (including a trusted pick) is unavailable or absent in
   capabilities -> `unavailable/specialist_unavailable` with that slug. Never replaced.
10. Otherwise `route/single_subject`.

`selectSticky` re-checks only catalogue membership and availability:
`route/sticky_subject`, `unavailable/sticky_invalid` or `specialist_unavailable`. No
phrase-triggered reclassification.

## How website 01 would call it

The adapter (owned by 01) maps Fastino output to `epinoic.routing-evidence.v1`; this
package never sees raw HTTP, prompt text or browser route IDs.

```js
import {
  buildLabelSet, loadApprovedPolicy, selectSpecialist, selectSticky,
} from "@epinoic/specialist-routing";

const labelSet = buildLabelSet(catalogue);            // once, at startup
const policy = loadApprovedPolicy(approvedPolicyJson); // throws until a reviewed calibration exists

// New subject (or an explicit "different subject" UI action):
const evidence = await adapter.classifyToRoutingEvidence({ excerpt, labelSet }); // 01's adapter
const result = await selectSpecialist({
  evidence, catalogue, labelSet, policy,
  capabilities: runtime.getCapabilities({ environment }),  // the runtime's object, unmodified
  trusted: profile ? { courseSlugs: profile.courseSlugs } : {}, // server-derived only
  options: {
    limits: { maxExcerptUtf8Bytes },                          // the adapter's excerpt bound
    calibrationContext: { model, datasets: { tuneSha256, holdoutSha256 } }, // from the calibration record
  },
});

// Follow-up turn on a stored subject: no inference, no calibration needed.
const followUp = await selectSticky({ stickySlug: conversation.subjectSlug, catalogue, capabilities });

switch (result.outcome) {
  case "route":       /* hand result.slug to the specialist runtime */ break;
  case "clarify":     /* UI copy keyed by result.reason, options from result.candidates */ break;
  case "unavailable": /* UI copy keyed by result.reason; never substitute another specialist */ break;
}
```

## Calibration fingerprint

`computeCalibrationFingerprint(identity)` is SHA-256 over the canonical JSON of
`{ model, labelSetSha256, catalogueSha256, policySha256, adapterVersion, excerptVersion,
datasets: { tuneSha256, holdoutSha256 } }`. Every field is required; no other field is
accepted. `policySha256` excludes `thresholds` (contract section 7) and `calibration`
(it holds the fingerprint).

At selection time the router assembles the identity itself: catalogue and label-set
digests and `policySha256` are computed, `adapterVersion` and `excerptVersion` come
from the evidence, and `model` and `datasets` come from `options.calibrationContext`
(the contract's signature has no other place for them). Any difference gives
`calibration_mismatch`. Because thresholds are outside the fingerprint, a threshold
edit must come with a `policyVersion` bump, which is covered.

The fixture fingerprint (`a02cf817...93593`) binds the fixture policy to the synthetic
catalogue, label set, harness identifiers and the eval-set split digests. Thresholds
were not fitted to that data. Run `npm run build:fixtures` after editing the overlay
(and rebuilding the catalogue), the eval set or the fixture policy.

## Synthetic evaluation set and evaluator

```
npm run evaluate     # node tools/evaluate.mjs
```

The report header is verbatim: `POLICY-MECHANICS TEST OVER SYNTHETIC SCORES — NOT
PROVIDER OBSERVATIONS, NOT CLASSIFIER ACCURACY. No model was called.`

- **260 items** (tune 153, holdout 107) in 201 groups (tune 121, holdout 80). Every
  message is original and student-style; none comes from official papers, student
  conversations or the website's frozen set.
- Split = `"tune"` when the first byte of SHA-256(group) is below 154, else
  `"holdout"`. The evaluator recomputes it and fails on mismatch or a group crossing
  splits.
- Coverage: all 16 subjects have at least 3 single-subject items in each split
  (english-a-literature and english-specialist via trusted-course and sticky items,
  because text alone cannot separate them until decision 2), and all 17 boundary tags
  have at least 2 items per split: generic-english, generic-maths,
  english-variant-specific, maths-variant-specific, overlap-environment,
  mixed-subjects, mixed-supported-unsupported, unavailable-recognised, out-of-scope,
  unsupported-language, language-vs-subject, needs-task-context, prompt-injection,
  long-message (`compose` generators with the cue beyond the 2048-byte head excerpt),
  excerpt-edge (exact 2048 bytes, one byte over, three- and four-byte characters
  straddling the boundary), trusted-course-metadata, sticky-follow-up.
- Cross-split near-duplicates (token-set Jaccard >= 0.8): **0**. Disputed items listed
  for review: **9**, each with a `disputeNote`.
- Every non-sticky item carries `syntheticEvidence` with
  `kind: "hand-assigned-synthetic-scores"`: scores chosen to represent the intended

  present but `available: false`: physics, ess; the other nine absent).
- Policy mechanics: **260 pass, 0 fail, 0 not run** (tune 153/153, holdout 107/107).
  Codes exercised by the set: all route and clarify reasons, plus
  `specialist_unavailable`, `out_of_scope`, `unsupported_language`, `sticky_invalid`;

## Contract gaps resolved (fail-closed) in this implementation

1. **No reason codes for configuration errors.** Mapped as in the table under "Result
   codes" instead of adding codes or throwing.
2. **`selectSpecialist` has no `limits` and no source for `model`/`datasets`.** Added
   `options.limits` and `options.calibrationContext`; missing means
   `evidence_invalid` / `calibration_mismatch`.
3. **"English A: Literature" naming.** The contract makes "English literature"
   family-level; this package also treats "english lit", "english a literature" and
   "english a: literature" as family-level, and gives english-a-literature and
   english-specialist no leaf aliases until decision 2.
4. **Family signals in the mixed check.** A family signal counts as a topic, so
   "English and History" is mixed; out-of-scope at threshold plus any topic is mixed.
5. **Margin boundary.** A gap equal to `marginMin` is within the margin (clarify).
   Separation in step 5 also requires `routeMin`.
6. **Trusted resolution.** Exactly one group member among the trusted courses, and
   (for overlap) it must be a near-top candidate; same-family near ties without a
   family signal (`competing_subjects`) are not resolved by trusted courses; a
   trusted pick still goes through the availability check.
7. **Offline capabilities.** `environment: "offline-test"` is refused outside the
   harness by both selection functions (`selectSticky` takes an optional `options`).
8. **Capabilities consistency.** `available: true` requires a mode, a gate version and
   a bundle digest.
9. **Catalogue evidence.** `subjects[].evidence = { path: "<packagesPath>/<slug>",
   sha256: <package digest> }`, which must equal `source.packageDigests[slug]`. Real
   mode does not change `slugStatus`; the roster owner updates `slugSource`.
10. **Policy consistency.** Thresholds in (0, 1], `marginMin < routeMin`,
    `clarifyFloor <= routeMin`; `fixtureBrand` required exactly for `fixture-only`.
11. **Forbidden fields** are matched by name anywhere in catalogue and evidence
    (provider, model, key, secret, token, enable/enabled, availability; plus route,
    slug, override, specialist, agent, target in evidence).

## Unresolved decisions (contract section 9)

Recorded in the overlay and catalogue `unresolvedDecisions` with their interim rule:
real folder slugs for ten provisional subjects; `english-specialist` scope; the
website's `english` route ID mapping (01); a trusted course-metadata source (until it

capacity and shape; SL/HL kept out of routing.

## Completing against the real source

1. Get a clean checkout of `Epinoic-AI/Epinoic-Agent-Training` at the pinned commit and
   confirm the real folder names; update `agents/agents.json` (`slugSource`) and the
   overlay slugs and `slugStatus` together (decision 1).
2. Add any non-package directories under `knowledge-bases/` to `overlay.excluded`.
3. Build the real catalogue (refuses unless HEAD equals `--commit`, the tree is clean,
   every slug has a directory and every directory is a slug or excluded):
   ```
   node tools/build-catalogue.mjs --kb /path/to/Epinoic-Agent-Training/knowledge-bases \
     --commit <40-hex> --overlay catalogue/routing-overlay.json \
     --roster ../agents/agents.json --out <catalogue.json>
   ```
   Per-package digest: SHA-256 over the sorted lines `relativePath\0sha256(file)\n` of
   the package's git-tracked files.
4. Rewrite each `teachingScope` from the package's master prompt, then review aliases.
5. Resolve decisions 2 to 7 and update the overlay and eval expectations.
6. Have website 01 confirm the label set against the real Fastino contract and measure
   token counts; map adapter output into the evidence schema.
7. Calibration owner: score the eval set with the real adapter, fit thresholds on
   tune, report on holdout, then issue an `approved` policy and calibration record.
8. Re-run `npm test`, `npm run evaluate` and `npm run check:portable`.

## Limitations

- Synthetic catalogue; teaching scopes and aliases are hand-written, not read from the
  packages. Ten slugs are provisional.
- The evaluator tests policy mechanics over hand-assigned scores. It says nothing about
  classifier accuracy or provider behaviour.
- Label-set compatibility with GLiNER-2.5-Decide and token fit are unverified.
- The harness excerpt (first 2048 UTF-8 bytes on code-point boundaries) is a stand-in;
  website 01 owns excerpting. Long-message items show that head-only excerpts can hide
  a late subject cue.
- The synthetic capabilities mark five subjects available only to exercise route
  paths. The real runtime currently reports every entry `available: false`.
- Real mode was tested only against temporary git repositories with fake packages.
